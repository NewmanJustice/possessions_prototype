## Technical Decisions & Patterns

1. **Error Handling Pattern:**
   - Store errors in `req.session.errors`
   - Build `errorList` for GOV.UK error summary
   - Build `fieldErrors` object for inline field errors
   - Pass both `errors` array (for title prefix) and separated error objects to template

2. **Conditional Reveals:**
   - Used GOV.UK Nunjucks macros with `conditional.html` pattern
   - Nested conditionals for multi-level reveals (defendant address)

3. **Date Input:**
   - Used hyphenated field names (`startDate-day`) matching GOV.UK pattern
   - Bracket notation for destructuring: `req.body['startDate-day']`
   - Stored as object: `{ day: '01', month: '04', year: '2021' }`

4. **Session Data Structure:**
   - Flat properties for simple data
   - Nested objects for complex structures (addresses, dates)
   - Arrays for collections (defendants, documents)

5. **Validation Approach:**
   - Server-side only (no client-side JavaScript)
   - Return 302 redirect on error (PRG pattern)
   - Preserve form values on error for repopulation

6. **Template Whitespace:**
   - Used `{%- ... -%}` in layout pageTitle block to strip newlines for test regex matching
